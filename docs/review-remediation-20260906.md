## 固定研究问题与四组账户

`configs/research/review_experiment_v1.json` 在读取新前瞻结果前固定实验。A 为修复后的原 V5 小时决策管线，使用自己账户的现金、持仓、峰值和风险状态；B 复用现有 participation 绝对方向与可执行预算优先、相对排名在后的内核；C 仅把 B 最长持有期从72小时改为24小时；D 仅在 C 新入场时读取此前实际收到、仍有效的24小时 DEFER。无参考、过期、NO_VIEW 均保留 C；退出始终不读取参考。原模拟 cohort 的文件和策略内核未改动，不合并其收益。

A 的比较范围是原 V5 **小时决策管线加共同报价执行模型**，不宣称完整复刻实盘事件执行器、撮合优先级或交易所账户。研究进程没有执行引擎和下单能力；原管线适配器在自己的目录运行且禁止联网。只复制显式只读配置和当时公开交易规格，任何未具备的离线输入导致显式失败，不回填实盘账户状态。

四组均100 USDT独立起始权益，30/60/120 bps三档成本（每边10 bps费用，其余为滑点假设；实际买卖价差另由 ask/bid体现）。费用和币种是显式研究模型，不是已校准实盘费率。所有成交必须使用意图之后真正采集到的报价，检查时效、数量步长和最小数量。买入币本位费用、卖出USDT费用和残余尘埃独立记账；不删除零头、亏损或持仓成本。最小10 USDT是共同研究下单约束，交易所最小数量/步长取采集时公开规格。

新 `run_review_forward.py` 每分钟采集公共报价，每小时更新600根闭合K线；各组小时形成新信号，候选持仓可在后续报价检查硬退出。缺口后取消未成交新增风险意图，不补造缺失成交。SQLite保存原始输入、数据哈希、每组事件和检查点；代码、实验或策略哈希变化拒绝续写旧实验。中途崩溃保留处理标记，要求审计回放至新目录，不能悄悄重置账户继续。

汇总以净权益增量、全分钟最大回撤、清算价值、手续费、暴露时间及资金使用率为主。另给三档成本、去最大盈利已完成持仓周期、逐日/状态分段、成对连续3日块 bootstrap 95%区间、独立24小时机会与重叠观察。参考否决只在 C 和 D 同时出现同一入场机会且 C 完成模拟持仓周期后计避免损失/错过净利润；事后最大涨幅不作为成交或收益。云/API固定月费用尚未提供，项目净利润未验证。

预先要求至少30日、100个独立机会、10个入场日，再人工检查正净权益增益、置信下界、回撤、60/120 bps压力、去最大盈利和全部时段/状态。程序不自动提高真实仓位，达到样本门槛也只能提交人工复核。

## 尚不能宣告通过的验收

- 已看过的60日数据只用于诊断，缺少当时完整交易规格和足够密集的可观测报价，不能声称已经完成严格同资金历史A/B，也不算样本外。
- 当前权重对照缺少通过新契约的历史动态报告；因此冻结静态基线，静态/动态净组合收益结论为证据不足。
- 前瞻区间、独立机会、置信区间及真实增益需要采集后形成；初始状态应为 `INSUFFICIENT_FORWARD_EVIDENCE`。
- 全量测试、Linux锁/紧急退出分支、GitHub CI、发布物与在线逐文件一致、回滚演练和自然运行验证必须以最终交付记录为准。

## 风险与回滚

严格收益契约会拒绝仍提供含混旧预测字段的新增风险；不通过猜测字段语义恢复许可。冻结动态权重会改变部分分数，但没有删因子或放大风险。新研究及参考服务失败只影响对应报告，并显式报错。发布保留原代码目录和账本路径，回滚仅切代码指向并恢复原服务/定时器状态；不得恢复旧数据库覆盖新订单、成交或权益状态。
