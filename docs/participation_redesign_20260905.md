# V5 行情参与与收益问题：诊断和程序改造

**结论：低收益主要来自有效入场被多层否决、资金长期空置，以及方向、排名、持有和风控恢复的职责混用。单纯增加交易次数没有稳定增益。** 本次修复实际运行链中的错误，并把新的方向/排序/风险预算策略做成历史回放和真实周期共用的内核，接入 V5 小时任务与独立组合账本。

数据截止北京时间2026-09-05 08:00。本次生产证据包含336个小时决策；1,196个可比价格与OKX已完成小时K线一致。四币最近72小时涨幅分别为 BTC +2.8747%、ETH +1.5430%、SOL +1.9100%、BNB +5.6223%。正常交易、对账、账本及事件服务运行成功；kill switch关闭，对账/账本正常；账户现金106.86074454 USDT，历史峰值132.12063609 USDT、回撤19.1183%，风险档位PROTECT，当前无实质仓位。最新真实成交仍为8月28日SOL平仓，该轮含双边手续费净利0.24921360 USDT。

**为何交易不积极**

| 环节 | 当前证据 | 实际影响 |
|---|---|---|
| 方向与排名混用 | Alpha6用自身分数减全币均值的正负生成买卖；多策略随后把它与趋势方向融合 | 广泛上涨时相对落后的币可被标为卖出，已有上涨候选在到达路由前就消失 |
| 重复确认 | 72小时44个目标全部被挡：RSI弱21、trend-only22、Alpha分低1 | 52个Trending时段仍未生成入场订单 |
| 分数门槛不相容 | 72个Alpha买入信号最高0.1313，0个达到正常0.4门槛；45个是fallback buy | 保底生成买入并没有带来可执行机会；相对分数也不是预期净收益bps |
| 首选过早截断 | 旧组合先按PROTECT单仓截断，再对首选执行入场检查 | 第一名不可执行时，后续合格标的可能没有替补机会 |

72小时被挡候选的4小时估算平均扣费结果为−26.3bps，8小时−9.2bps，24小时+176.2bps。不同持有期样本数不同，候选重叠，不能累加成可实现收益；它提示短线频繁进出与延长趋势持有的结果差异很大。行情涨幅也不能直接当成约106 USDT小账户能挣到的钱：10.5 USDT仓位上涨2%，毛利仅约0.21 USDT，还需扣费用。提高仓位会同时提高亏损，不作为补救收益不足的默认手段。

**改造后的程序分工**

1. 绝对方向：已完成小时K线close在EMA20上方，EMA20四小时斜率为正，四小时动量达到80bps和1.5倍成本储备中的较大者。观测动量明确不叫“预期盈利”。
2. 相对排序：先检查完整四币的方向和可执行预算，再用历史权重重建因子排序；新候选剔除F4成交量扩张的排序贡献，不再让相对分正负生成买卖方向。
3. 组合预算：一份现金、一仓，目标8%、总仓上限15%、最小订单10 USDT加5%缓冲。每笔计划亏损不超过权益0.25%，同时受剩余日亏损额度1 USDT和试验3%回撤额度限制。最小订单超预算就明确拒绝，不能临时抬高风险上限。
4. 持有和退出：价格失效止损与费用分开，默认价格120bps止损；EMA20趋势失效、72小时持有期限、Risk-Off和试验回撤规则退出。三个预先声明的止损对照均使用同一内核，不以调参追求正数。
5. 决策与成交：本轮只生成意图，后续真实观测报价才可模拟成交；成交前重验方向、成本、价差、资金及风险。买ask、卖bid，单边手续费10bps、基础滑点5bps；不重复扣价差。
6. 前瞻账本：生产main.py获取新鲜top-of-book后调用共用内核。SQLite事务一次保存组合状态和决策事件；重复/倒序小时不重复成交，缺失观测不回填交易，策略与源码哈希变化要求显式新队列，不能混入旧收益。状态文件仅允许在运行报告目录的participation子目录。

前瞻输出为每轮 `participation_forward.json`、`reports/participation/latest.json` 以及 `reports/participation/forward.sqlite`。它使用独立虚拟资金，不向真实orders列表追加交易；配置 `mode=forward_paper` 不能直接切成live来宣称已验证。每小时持续推进组合，不再只有无持仓的候选标签。

**风险与回滚**

本次实际修复不能消除未来行情和成本风险；新策略须积累完整、足够多且不依赖单次行情的前瞻闭环，再决定是否授权真实资金。当前约19.1%真实历史回撤仍为PROTECT，新策略默认不自动解除它。

已发现但没有扩展修改的历史风险包括：指定BNB旧仓位的profit-only特殊规则可能挡固定止损（其锚点不适用于新仓），以及旧预算变更路径可能缩放局部峰值而未同比缩放权益。当前无该BNB旧仓，budget cap为null，后者未触发；它们不是本次72小时无成交的原因，不应靠修改这些值抹掉历史回撤。

回滚以部署时的逐文件备份和哈希为准，恢复本次13个生产文件；其他现场修改保留。候选停止观察可关闭 `participation.enabled`，保留SQLite原始证据。旧恢复脚本的废弃修改入口不能作为回滚后的风险升级办法。本次Git分支基线为322fe75a，上一轮离线研究数据仍完整保留。
