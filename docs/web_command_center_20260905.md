# V5 交易控制台改版

旧首页难以把账户、决策原因、实际成交和策略验证连起来，而且部分接口的空值、旧快照和占位指标容易被误解为当前事实。本次重做首页信息结构，围绕“现在持有什么、为什么没交易、什么时候再决策、程序是否正常”展示。

## 展示内容

- 交易总览：真实权益、有效持仓市值、峰值回撤、近 72 小时真实成交订单、下一次决策时间、权益历史与现金分布。
- 行情与机会：逐币决策参考价、Alpha 排序分、目标仓位、筛选及路由原因；展开可看 K 线和全部可见依据。
- 持仓与成交：有效仓位与成交分开，买入/卖出筛选，同订单分笔成交合并，可展开最近 50 条。
- 策略验证：独立模拟资金、已实现净收益、闭环次数、逐币等待原因和观测进度。未授权实盘切换。
- 系统运行：停止开关、对账、账本、风险、定时器、接口成功率与延迟、研究权限实际是否参与拦截，以及证据导出入口。

桌面采用深色侧栏、分区和细线布局；手机采用横向导航、双列指标和逐币展开详情。支持键盘焦点、减少动画偏好。

## 数据口径与主要改动

- `src/reporting/dashboard_command_center.py` 新增只读汇总；`scripts/web_dashboard.py` 增加 `/api/command_center`，最多读取 104 个小时目录，文件大小有限制。真实成交来自只读 SQLite，并明确候选、订单意图、实际成交的统计单位。
- 前瞻报告须通过当前策略、代码和 SQLite 已提交事件的身份核验。缺失、部分观测、过期、未来时间和版本不匹配分别展示，不以零替代未知。
- `web/dashboard/src/App.tsx`、`api.ts`、`types.ts`、`commandTypes.ts` 独立刷新账户、决策、历史曲线及辅助状态；辅助请求不阻塞主账户首屏。失败保留旧记录并标记；成功空数组才清空成交和持仓。
- 新增 `CommandCenter.tsx`、`command-center.css`、`commandFormat.ts`、`EquityHistoryChart.tsx`、`equity-history-chart.css`，替换首页，并更新入口 HTML、图标、应用清单及 `web/dist` 构建产物。
- 权益接口真实字段为 `value`，成功率为 0–1 比例，均明确转换。权益变化可能包含出入金，不标成交易净收益。省略旧接口硬编码的今日收益、胜率和 Sharpe 等占位指标。
- 权益读取改为最多 800 个文件、每文件最多 64 KiB，并按文件大小及纳秒修改时间缓存。相同生产数据隔离对比：读取 4315 个文件降到 800，原函数约 0.723 秒，新冷读约 0.115 秒、缓存约 0.096 秒，保留相同 800 个点。这是函数级测量，不代表完整首屏加速倍数。
- 新增后端汇总/曲线测试与前端数据/显示回归测试，更新对应既有首页契约断言。

## 边界、风险与回滚

本次只修改 Web 展示、只读聚合和权益查询，不修改交易参数、实盘订单逻辑、风控、仓位限额或定时任务。

主要风险为多接口观测时间不同、历史数据缺口以及浏览器保留旧资源。页面分别标注新鲜度和未知状态；只读汇总限制 I/O；图表按需加载。部署先写带哈希的新资源，再启动兼容旧页面的后端，检查通过后最后替换 HTML；保留旧资源供已打开页面使用。

部署以源文件 SHA256 检查漂移并备份，仅重启 `v5-web-dashboard.service`。回滚只恢复本次写入文件和旧 HTML，保留带哈希资源，再重启 Web 服务，不操作交易服务或服务器 Git 工作树。具体提交号、测试和生产验证见交付记录。
